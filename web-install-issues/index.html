Web Install DevTools Issue Test Site

Internal test site for the Web Install API's DevTools Issue reporting. Every scenario here is expected to fail installation; the point is to verify the DevTools Issue each failure produces. Do not expect a successful install on any page in this directory.

What you need

  • A Chromium / Edge build that includes the Web Install API (navigator.install() and the <install> element) and the DevTools Web Install Issue reporting changes under test.
  • Enable both feature flags:
    • about://flags/#web-app-installation-api → Enabled
    • about://flags/#web-app-install-element → Enabled
    Restart the browser after toggling.

How to run a scenario

  1. Open DevTools, then More tools → Issues. Keep the Issues panel visible.
  2. Open one scenario link below in the same tab.
  3. Click the navigator.install() button and read the Issue. Confirm the page-visible result matches the expected DataError / invalid_data.
  4. Reload the scenario page (or clear Issues) before triggering the other entry point. Identical Issues deduplicate, so a reload is the reliable way to see the second entry point produce its own Issue.
  5. Repeat every scenario in an Incognito / InPrivate window to confirm the diagnostic behavior is profile-independent.

Current-document entry points

Zero-parameter navigator.install() and untargeted <install>. These consult the current document's linked manifest.

1. No manifest

Web Install Issue
No manifest detected — no manifest URL and no affected request are reported.
Page-visible result
navigator.install() rejects with DataError; <install> returns invalid_data.
Open scenario

2. Malformed manifest

Web Install Issue
Manifest could not be fetched, is empty, or could not be parsed, associated with the linked manifest URL.
Open scenario

3. Missing manifest ID

Web Install Issue
Manifest does not contain an id field, associated with the linked manifest URL.
Open scenario

4. Invalid start_url

Web Install Issue
Manifest start_url is not valid, associated with the linked manifest URL.
Open scenario

5. Missing name and short_name

Web Install Issue
Manifest does not contain a name or short_name field, associated with the linked manifest URL.
Open scenario

6. Cross-origin manifest (CORS-blocked) — privacy boundary

Web Install Issue
No Web Install Issue is reported. Current-document Issues are intentionally suppressed when the linked manifest is on a different origin from the document, to avoid exposing cross-origin fetch details.
Other Issues
A CORS Issue from the browser blocking the manifest fetch is expected. The remote manifest is never actually consumed, so its body (valid or malformed) does not affect this scenario.
Page-visible result
navigator.install() still rejects with DataError; <install> still returns invalid_data.
Open scenario

What this site does not do

So that DevTools Network / Storage activity you observe here can be attributed to the API under test rather than to this site, these pages intentionally do the minimum:

  • No analytics, telemetry, beacons, or any fetch() to a logging endpoint.
  • No cookies, no localStorage, no sessionStorage, no IndexedDB, no service worker.
  • No third-party scripts, stylesheets, fonts, or CDN assets.
  • No form fields, so nothing you type or click is collected or transmitted.
  • The only outbound requests are the manifest fetches that the Web Install API itself triggers (plus the one cross-origin manifest URL in scenario 6, which is the behavior being tested).
